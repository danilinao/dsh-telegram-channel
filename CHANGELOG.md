# История версий

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии — SemVer.

## 0.12.0 — 2026-10-23

Пульт перестал быть «только текстом»: уведомления стали действиями, файлы —
частью диалога.

### Добавлено
- **Кнопки под уведомлениями о ходе.** «🔁 Повторить» после ошибки (повторяет
  последний отправленный в эту сессию текст), «▶ Продолжить» после лимита
  выходных токенов (отправляет «Продолжай с того места, где остановился»),
  «📜 Последний ответ» и «📖 История». Callback несёт id сессии, поэтому
  работают и уведомления по чужим (непривязанным) сессиям.
- **`/retry`** — повтор последнего запроса (после ошибки провайдера), работает и
  из команды, и кнопкой.
- **`/find <текст>`** — поиск сессий по названию или папке; результат — кнопки
  привязки.
- **Текстовые документы** — `txt`, `md`, `json`, `yaml`, `csv`, код (`.gd`,
  `.ts`, `.py`, …) до 128 КБ приходят в сессию текстом вместе с подписью;
  бинарные файлы получают явный отказ.
- **Напоминание о неотвеченном вопросе** — через 5 минут бот один раз пишет
  «⏳ вопрос всё ещё ждёт ответа»; таймер не держит процесс и снимается при
  любом ответе, `/cancel` или ответе из Web.

### Изменено
- `enqueueNotice` принимает inline-клавиатуру; уведомления по-прежнему идут
  последовательной очередью на чат.
- `followupBound` вынес общий `deliverPrompt` — повтор и продолжение шлют
  текст в конкретную сессию, не требуя привязки.

## 0.11.0 — 2026-10-23

Вопросы агента и запросы разрешений теперь закрываются кнопками — на телефоне
не нужно вспоминать буквы вариантов.

### Добавлено
- **Inline-кнопки для `ask_user_question`.** Каждый вопрос приходит отдельным
  сообщением с кнопками вариантов (`A. Fast`), кнопкой «✏️ Свой ответ» и, для
  мультивыбора, «✅ Готово». Выбранное отмечается галочкой прямо в клавиатуре,
  после ответа сообщение превращается в «✅ вопрос / Ответ: …», а клавиатура
  снимается.
- **«✏️ Свой ответ»** — следующий текст из чата уходит как `custom` для этого
  вопроса; если вариантов нет (открытый вопрос), работает обычный ввод текста.
- **Кнопки «✅ Разрешить» / «⛔ Отклонить»** у запросов разрешения инструментов
  вместо [A]/[B].
- Текстовые ответы остались: буква варианта, свободный текст и построчный
  формат `1:/2:` — обратная совместимость и старые сообщения работают.

### Изменено
- `TelegramClient` умеет `editMessageText` / `editMessageReplyMarkup` —
  клавиатуры снимаются или обновляются на месте, без новых сообщений.
- `/help` упоминает кнопочные ответы.

## 0.10.0 — 2026-10-22

Настройки плагина переехали туда, где их ищут: вкладкой в «Настройках», как у
cost-meter и plugin-market.

### Добавлено
- **Вкладка «Telegram» в «Настройках»** — форма регистрируется в слот
  `settings.section` (`id` = имя пакета, `order` = 40), а не только в карточку
  плагина. Заголовок вкладки — thunk-функция из словаря плагина, поэтому он
  следует за активным языком (`ru` / `en`) без перерегистрации слота.
- **Заголовок страницы** («Telegram-пульт» + пояснение) — карточка в Plugins
  приносила свой заголовок, у вкладки его не было.

### Изменено
- Карточка **Plugins → dsh-telegram-channel-ru** осталась вторым входом в тот
  же `configForms`-скоуп: обе точки рендерят один компонент, поэтому
  поведение и сохранение идентичны.

## 0.9.1 — 2026-10-22

Рассуждения модели теперь доходят до Telegram — спойлером, как и вызовы
инструментов.

### Исправлено
- **Рассуждения не приходили в чат, хотя команды приходили.** Бот ждал
  потоковые `assistant/chunk`, а на DSH 0.2 в `session/event` их нет: думанье
  модели лежит готовым блоком `{type:'reasoning'}` в финальном
  `assistant/message`. Теперь спойлер «🧠 Рассуждения» собирается из этого
  блока и уходит перед ответом; потоковый путь оставлен фолбэком и не даёт
  дубля (если в сообщении есть рассуждение, буфер потока отбрасывается).

### Добавлено
- **`/reasoning on|off`** — присылать ли рассуждения в этот чат (по умолчанию
  `on`, выбор сохраняется в состоянии бота). `/reasoning` без аргумента
  показывает текущее состояние.
- Тесты: `tests/reasoning.test.ts` — 6 случаев (спойлер перед ответом,
  сообщение без текста, выключение по чату, состояние команды, фолбэк потока,
  отсутствие дубля). Всего 106 тестов, `npm run check` зелёный.

## 0.9.0 — 2026-10-22

Настройки переехали в Web-интерфейс, и пользователей стало можно несколько.

### Добавлено
- **Страница настроек в GUI.** `Plugins → dsh-telegram-channel-ru`: токен,
  список пользователей, доступ, формат сообщений, лимиты. Браузерная половина
  (`client/client.js`, слот `plugins.bundle.config`) собирает правки в одну
  атомарную запись профиля и пишет только изменённые поля.
- **Живое применение без рестарта `dsh`.** Все поля Config помечены
  `.volatile()`; плагин слушает `loader/volatile-update`, останавливает старый
  мост (long-poll теперь прерывается по `AbortSignal`, а не ждёт таймаута) и
  поднимает новый с новыми значениями. Смещение `getUpdates` переносится,
  поэтому уже обработанные сообщения не обрабатываются дважды; при смене
  токена (другой бот) смещение сбрасывается.
- **Несколько пользователей.** `users: [{ id, name?, enabled? }]` — список из
  GUI, у каждого своя галочка «Отвечать». Плоский `allowedUserIds` из 0.8.x
  остаётся фолбэком, пока `users` пуст; первое сохранение из GUI переносит
  список и убирает старый ключ, чтобы не было второго, невидимого белого списка.
- **Добавление по `@username`.** Страница зовёт `/settings/resolve`, хост
  резолвит `getChat`; рядом — чипсы «недавно писали боту» из запомненных имён.
- **Токен как секрет.** `.role('secret')` — DSH вырезает токен из документа
  настроек, страница показывает «сохранён» и живой статус «Бот подключён:
  @имя» (через `getMe`), а не сам токен.
- **Два хост-маршрута** `/plugins/dsh-telegram-channel-ru/settings/{info,resolve}`
  (только несекретные сведения; `no-store`, same-origin проверка на POST).
- **Имена людей в состоянии бота** и сохранение `getUpdates`-смещения в
  `telegram-channel-bindings.json`.
- **Браузерная проверка страницы** — `npm run test:browser`: настоящий React и
  headless Chrome, 19 проверок (рендер, статус, добавление по `@username`,
  пакетная запись, снятие галочки, удаление, предупреждение «разрешить всем»).
  Не входит в `npm run check` (нужен Chrome).

### Изменено
- `npm test` — 99 тестов (было 62): конфиг/белый список, маршруты настроек,
  несколько пользователей, проводка браузерной половины.
- `apply` разложен на `apply` + `applyWith(ctx, config, options)`: клиент
  Telegram внедряется в тестах, сеть в тестах не нужна.

### Известные ограничения
- Бот по-прежнему не разделяет доступ к сессиям между пользователями: каждый из
  списка видит все рабочие области и может привязаться к любой сессии.
- Страница настроек требует DSH 0.2.x (в 0.1.x у Plugins нет форм).

## 0.8.2 — 2026-10-22

Первая версия, ушедшая в npm из CI, а не с рабочей машины.

### Добавлено
- **`.github/workflows/publish.yml` в репозитории.** Публикация на тег `v*`:
  `npm ci` → `npm run check` → `npm publish --provenance` через Trusted
  Publishing (OIDC). Токенов и секретов в репозитории нет; если версия уже
  в реестре, шаг публикации пропускается, а расхождение тега и версии в
  `package.json` валит сборку.
- **Provenance.** У версии на npm появляется провенанс-аттестация: видно, из
  какого коммита и какой workflow она собрана.

### Изменено
- Старый пакет `dsh-telegram-channel@0.8.0` удалён из реестра — остаётся только
  `dsh-telegram-channel-ru`.

## 0.8.1 — 2026-10-22

Пакет и репозиторий переименованы, публикация переехала в CI.

### Изменено
- **Имя пакета и репозитория: `dsh-telegram-channel` →
  `dsh-telegram-channel-ru`.** Суффикс отделяет русское ответвление от
  оригинала (`hi-wenw/dsh-telegram-channel`) в общем пространстве имён npm.
  GitHub редиректит старые адреса, `npm i dsh-telegram-channel@0.8.0` продолжает
  работать (старое имя осталось опубликованным). Вместе с пакетом изменился
  `id` плагина в профиле DSH — строка с токеном в
  `~/.dsh/profiles/web/cordis.patch.yml` должна быть
  `- id: dsh-telegram-channel-ru` (порядок переезда — в README).
- **Публикация в npm — из GitHub Actions.** Workflow
  `.github/workflows/publish.yml` на тег `v*`: `npm ci` → `npm run check` →
  `npm publish --provenance` через Trusted Publishing (OIDC), без токенов в
  репозитории и без секретов. Если версия уже в реестре, шаг публикации
  пропускается; расхождение тега и версии в `package.json` валит сборку.
  Локальный `./PUBLISH-npm.sh` остаётся запасным путём (без provenance).

### Добавлено
- Тест, который сверяет имя пакета, `export const name` плагина и `id` в
  `cordis.patch.yml` — разъехавшиеся имена ломают id-оверрайд с токеном.

## 0.8.0 — 2026-10-21

Проект стал самодостаточным: собирается, тестируется и пакуется на месте.

### Добавлено
- **Сборка из исходников.** `npm install && npm run build` компилирует
  `src/*.ts` → `lib/*.js` + `.d.ts` (tsc, `strict`, NodeNext). Ручное
  дублирование кода между `src/` и `lib/` больше не нужно.
- **`npm run check`** — typecheck → build → тесты → проверка свежести сборки.
- **`npm run test:lib`** — два теста, которые падают, если `lib/` не собран из
  текущего `src/` (паритет экспортов и текстов команд).
- `BUILD.md` — сборка, проверки, упаковка, установка, релизный цикл.
- `CHANGELOG.md` (этот файл).
- **Опубликовано на npm** —
  [`dsh-telegram-channel@0.8.0`](https://www.npmjs.com/package/dsh-telegram-channel):
  плагин ставится без клонирования (`dsh plugin --profile web add
  dsh-telegram-channel`). Публикация — `./PUBLISH-npm.sh`, токен `NPM_TOKEN` из
  хранилища DSH.

### Исправлено
- **Живые сессии больше не считаются пустыми.** Сессия из `catalogFromLiveAgents`
  помечается названной и не скрывается, если её журнала ещё нет на диске; в
  `ensureSessionNames` пустой считается только «холодная» сессия без сообщений.
  Раньше сессия, запущенная только в памяти, могла исчезнуть из выбора.
- **Старт не падает на частичном клиенте.** Карточка бота
  (`setMyShortDescription` / `setMyDescription`) вызывается только если метод
  есть у клиента.
- Типы приведены в порядок: 13 ошибок `tsc` (сужение union событий
  `assistant/chunk` / `todo/write`, `contentToText`, `projectionTitle`,
  неопределённая `cwd` в `resolveSessionTitleFromHost` — из-за неё имя холодной
  сессии молча терялось).

### Изменено
- **Тесты: 62/62.** Изолированы от реального хоста (`DSH_HOME` и
  `DSH_TELEGRAM_BINDINGS_FILE` указывают в temp), ожидания переведены с
  китайских строк upstream на русские, обновлены под текущее поведение
  (кнопка «новый проект», история при привязке, форматы `/status` и `/compact`).
- **Peer-зависимости** `@deepseek-ai/dsh-agent|dsh-llm|dsh-session` —
  `^0.2.1-alpha.2`, `cordis` `^4.0.5-alpha.1`, `schemastery` `^3.18.5-alpha.1`:
  рантайм `0.2.1-alpha.2` удовлетворяет им, поэтому исключение
  `allow-version` не требуется.
- `devDependencies` — точные версии, с которыми работает хост (проверка типов
  по настоящим типам, а не по заглушкам).
- `npm test` использует `tsx`; `npm run test:native` — то же на нативном
  стриппинге типов Node 26.
- `.gitignore` переписан (без BOM), добавлены `.tmp/`, `*.tgz`, `coverage/`.
